# Spoken fall check-in (protocol 2)

The phone keeps motion processing independent from camera, voice and networking.
A confirmed local fall collects a one-second burst targeting seven JPEGs; no MP4
is created or uploaded. Modal sends usable frames to Claude together. A visual
negative finishes this event and sensors keep monitoring; unavailable is never
interpreted as a negative. Only a recent visual positive can start enabled voice.

| Step | Behavior |
| --- | --- |
| Visual positive | Wait at least three seconds from receipt, prepare HFP, ask “Are you okay? Tell me how you feel.” |
| Full reply reports injury/distress/uncertainty | Ask “Would you like me to email your emergency contact?” |
| Full reply clearly reports being fine | Ask “Are you sure you do not want me to email your emergency contact?” |
| Yes to the email question | Send one email with the original reply, event, configured person name and optional phone location |
| Yes to confirming no contact | Finish without email |
| No to confirming no contact | Ask the explicit email question |
| No to emailing | Finish without email |
| Ambiguous consent | Clarify once; continued ambiguity requires manual review and does not authorize email/call |
| Two healthy unanswered questions | Email automatically; describe no response and unknown consciousness |
| Email consent processed | Truthfully report submission or unconfirmed delivery, then ask separately about a call |
| Yes to calling | Save a call request and hand off to iPhone confirmation; no automated Meta AI call |
| No/unclear/no reply to calling | Finish; any email already sent remains sent |
| Microphone/route/recognition failure | Save an audio error; never manufacture silence or consent |

Each question has ten seconds by default to START a reply. If silent, repeat once
and allow another full window. A spoken answer can continue to a recognition
final/pause, bounded at 60 seconds. A recognizer that ends before the full window
is an error, not proof of no response. Original replies go to the LLM in full;
hearing a “yes” followed by pain does not stop transcription or mean “fine”.

## Enable and configure

Turn on **Spoken fall check-in**, granting microphone and speech permission. Fixed
questions are generated by ElevenLabs and prefetched into phone RAM. English is
default; Italian and 10/15/20/30-second start windows are available. User name and
one emergency contact phone number are editable locally. The email recipient is
configured on Modal and may differ from that phone contact.

Tap **Enable / refresh phone location for alerts** to request when-in-use location
permission and a measured fix. Only a fix within 15 minutes and <=1 km accuracy
is included, with timestamp and accuracy. Locked-phone updates are not guaranteed;
missing/denied/stale location is reported unavailable, never invented or relabeled
as current. Coordinates go to the email, not the reply-classification LLM.

Attached Modal secrets must all exist:

- `fall-secrets`: existing `API_KEY`, `ANTHROPIC_API_KEY`; optional `CHECK_IN_MODEL`.
- `email-sending`: Gmail settings described in [Email alerts](../../backend/EMAIL_ALERTS.md).
- `elevenlabs-voice`: `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, optional
  `ELEVENLABS_MODEL_ID` (default `eleven_flash_v2_5`).

The POC selects Rachel's legacy ID `21m00Tcm4TlvDq8ikWAM`; ElevenLabs documents
routing this ID to Janet, so it may sound different from older Rachel samples.
Keep credentials outside phone code, repository and logs. Deploy the matching
backend before enabling voice. `/health` publishes protocol version and
configuration booleans; booleans alone do not verify credentials or delivery.

## API and persistence

Authenticated `GET /check-in/prompt?language=en&kind=contact` returns `audio/mpeg`
with `X-Check-In-Protocol: 2`. Kinds: `check_in`, `contact`, `decline`, `call`,
`email_submitted`, `email_failed`, `call_handoff`. Non-default questions require
protocol 2, preventing an older server's generic question from becoming consent.

Authenticated `POST /event/{id}/check-in` accepts:

```json
{
  "event_id": "same-confirmed-event-id",
  "stage": "initial",
  "outcome": "response",
  "transcript": "No, I injured my leg",
  "language": "en",
  "unanswered_prompts": 0,
  "person_name": "POC wearer"
}
```

Optional `location` has `latitude`, `longitude`, `accuracy` (metres), and
`captured_at` (Unix seconds). Subsequent stages are `contact`, `contact_retry`,
`decline`, `decline_retry`, `call`. Response includes stage, validated initial
`analysis` or consent `decision`, `next_action`, and optional `notification`.
Out-of-order or changed submissions return 409; identical completed submissions
reuse their result. No reply uses `outcome=no_response`, null transcript and
`unanswered_prompts=2`. Legacy silence without that attestation requires manual
review. A silence result over five minutes after the preceding server conversation
step (or initial event creation) is retained without sending a late email.

The phone durably claims an event before speaking, preventing question replay
across duplicate responses/relaunches. Stage transcripts and outboxes/responses
are saved separately under private app storage, exported by the diagnostic tool.
Networking retries never re-speak or re-record a reply. The active conversation
waits up to 45 seconds after an unsuccessful submission for retry completion;
a remaining pending turn requires follow-up and does not replay questions later.
A later email submission is shown in status, but the phone does not invent a
spoken receipt after the active conversation has ended.

This POC runs one Modal container with per-event conversation locks. Atomic email
claims additionally prevent automatic repeat SMTP submission after ambiguous
acknowledgements; see retention/recovery limitations in the email guide. Vision
upload idempotency across concurrent requests remains separate unfinished work.

## Phone calls and hardware validation

A spoken yes to calling records intent only. The app releases its audio session.
If foregrounded with a valid configured number it opens `tel:`; iOS requires its
own confirmation. Otherwise the app shows a persistent **Call emergency contact**
button after unlock/reopen. A successful URL open does not prove dialing or
connection. DAT 1.0.1 has no public outbound Meta AI call command. A user can also
initiate a native glasses call themselves. CallKit is not a silent cellular-dial
replacement. Call audio can route over the glasses' Bluetooth HFP connection;
validate the route on the actual phone/glasses, using iPhone call audio controls.

HFP must match the connected glasses; no deliberate phone mic/speaker fallback.
DAT can pause or end on some firmware during HFP. The app records interruptions
and attempts reconnection after voice. Continuous sensor sampling, locked-phone
speech recognition, fresh GPS, and call routing are hardware-dependent, not
certified by offline tests. Force-quit recovery is not promised.

Speech uses on-device recognition when supported, otherwise Apple's service.
Only text goes to Modal/Claude; raw microphone audio is not persisted. Background
audio is used for the bounded active conversation. No emergency-services dispatch
or arrival of help is promised. SMTP acceptance is not human acknowledgment.
